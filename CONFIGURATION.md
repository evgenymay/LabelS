# Конфигурация LabelS (chrome.storage)

**Конфигурация** — это всё, что расширение записывает в `chrome.storage` при работе (плюс то же самое попадает в резервную копию импорта/экспорта целиком).

**Профиль** = именованная сохранённая конфигурация в storage (**ключ `profile_<timestamp>`** + строка в **`profile_index`**). Пункт «По умолчанию» при этом профилем не считается — отдельного blob в storage под него нет.

Отдельно: **`profile_last`** — автосохранённое состояние той же структуры, что у именованного профиля (фиксированный ключ, имя «Авто-сохранённый» в коде).

**Экспорт:** отдельного места хранения «для экспорта» нет. Функция экспорта читает **`chrome.storage.local`** и **`chrome.storage.sync` целиком** (`get(null)`), собирает объект **`{ local, sync }`** и сохраняет его в JSON-файл. Именованные профили попадают в файл как часть вложенного объекта **`sync`** (те же ключи **`profile_*`**, **`profile_index`** и т.д.). Импорт обратно заливает **`backup.local`** и **`backup.sync`** в соответствующие области storage.

Ниже — полный перечень по областям.

---

## `chrome.storage.sync` (основная конфигурация, с синхронизацией Firefox)

| Ключ | Что внутри |
|------|------------|
| **`settings`** | Объект ползунков: **`history_days`**, **`label_count`**, **`icon_width`**, **`columns_num`**. |
| **`search_engine`** | Строка движка поиска: **`google`** или **`yandex`** (иначе при чтении подставляется Google). |
| **`saved_domains`** | Массив элементов; у каждого минимум **`domain`**, **`count`**, **`visible`**; при ручной раскладке ещё **`gridCol`**, **`gridRow`**; часто есть **`date_added`**. |
| **`manualLayout`** | Логическое: включена ли ручная расстановка по сетке. |
| **`autoLayout`** | Логическое: использовать ли автоматическую раскладку координат при отрисовке. |
| **`savedProfileSnapshot`** | Снимок для UI выбора профиля: **`name`**, **`settings`** (те же 4 поля), **`defaultVisibleDomains`** (массив строк-доменов), **`syncProfileKey`** (строка-ключ профиля в sync), **`updatedAt`** (число). |
| **`profile_index`** | Массив записей **`{ name, key }`** — оглавление сохранённых профилей. |
| **`profile_<timestamp>`** | Именованный сохранённый профиль: **`name`**, **`settings`**, **`domains`** (массив с **`domain`**, **`count`**, **`visible`**, **`gridCol`**, **`gridRow`**), **`created`**. |
| **`profile_last`** | То же по форме, что именованный профиль (как выше): автосохранённое состояние под ключом константы **`profile_last`**. |

При удалении профиля из sync удаляется соответствующий ключ **`profile_*`** или другой ключ записи профиля; **`profile_index`** перезаписывается без этой записи.

**Дополнительно:** при первой миграции те же ключи конфигурации могут временно дублироваться в **`local`**, пока `getSyncedConfig` не перенесёт их в sync и не сделает `local.remove` для этих ключей — это не отдельная «вторая конфигурация», а тот же набор полей.

---

## `chrome.storage.local` (вспомогательное)

Не синхронизируется между устройствами так же предсказуемо, как sync.

| Ключ | Что внутри |
|------|------------|
| **`pendingAddDomain`** | Строка — домен, который попап просит добавить на newtab; после обработки ключ удаляют. |
| **`fav:<домен>`** | Строка data URL закэшированной иконки для этого домена (каждый домен — свой ключ). |

При сохранении нового именованного профиля один раз вызывается **`local.remove(['customDefaults', 'defaultVisibleDomains'])`** — это зачистка устаревших ключей, если они были; в текущей логике новая конфигурация профиля живёт в **`savedProfileSnapshot`** в sync.

---

## Итог для формулировки «конфигурация»

- **Ядро конфигурации приложения** лежит в **sync**: **`settings`**, **`search_engine`**, **`saved_domains`**, **`manualLayout`**, **`autoLayout`**, **`savedProfileSnapshot`**, **`profile_index`**, плюс произвольное число ключей **`profile_*`** / **`profile_last`** с телом профиля.

- **Локально** к конфигурации стоит относить **`pendingAddDomain`** (очередь действия) и **`fav:…`** (кэш изображений); они тоже пишутся при изменениях, но не описывают всё состояние вкладки целиком.
